# Build mpv for macOS arm64

This is a working note for the mpv_r Apple Silicon self-build trial.

The first successful test used mpv `v0.41.0` on an Apple Silicon Mac and was
packaged as a local `mpv_r` trial build.

## Status

- mpv `v0.41.0` builds successfully for macOS arm64.
- The generated `mpv.app` launches and plays video on Apple Silicon.
- The generated app bundle can be repackaged as `mpv_r.app`.
- The repackaged `mpv_r.app` launches faster than the previous Mac preview
  build in local testing.
- Basic mpv_r operations worked in local testing:
  - playback
  - frame step
  - playlist file movement
  - screenshot capture

This is still a trial build. It needs daily-use testing before becoming the
default Mac release build.

## Configure

The first successful build used a local Meson build directory:

```sh
meson setup build/mpv-r-arm64-local \
  -Dprefix=/Users/mba2026/Documents/codex_hisyo/VideoReviewPlayer/build-src/out/mpv-arm64 \
  -Dlibmpv=true \
  -Dobjc_args=-Wno-error=deprecated-declarations \
  -Dgl=enabled \
  -Diconv=enabled \
  -Dlcms2=enabled \
  -Dlua=luajit \
  -Djpeg=enabled \
  -Dplain-gl=enabled \
  -Dzlib=enabled \
  -Dcocoa=enabled \
  -Dcoreaudio=enabled \
  -Dgl-cocoa=enabled \
  -Dvideotoolbox-gl=enabled \
  -Dvideotoolbox-pl=enabled \
  -Dswift-build=enabled \
  -Dmacos-cocoa-cb=enabled \
  -Dmacos-media-player=enabled \
  -Dmacos-touchbar=enabled \
  -Dvulkan=enabled
```

## Compile

Swift/Cocoa module cache writes can fail if the compiler tries to write outside
the workspace. Use cache directories inside the build tree:

```sh
mkdir -p build/clang-module-cache build/swift-module-cache

CLANG_MODULE_CACHE_PATH="$PWD/build/clang-module-cache" \
SWIFT_MODULE_CACHE_PATH="$PWD/build/swift-module-cache" \
meson compile -C build/mpv-r-arm64-local -j4
```

## Bundle

Generate the macOS app bundle:

```sh
CLANG_MODULE_CACHE_PATH="$PWD/build/clang-module-cache" \
SWIFT_MODULE_CACHE_PATH="$PWD/build/swift-module-cache" \
meson compile -C build/mpv-r-arm64-local macos-bundle
```

The generated app was:

```sh
build/mpv-r-arm64-local/mpv.app
```

## Verify

```sh
file build/mpv-r-arm64-local/mpv
build/mpv-r-arm64-local/mpv --version
file build/mpv-r-arm64-local/mpv.app/Contents/MacOS/mpv
codesign --verify --deep --strict --verbose=2 \
  build/mpv-r-arm64-local/mpv.app
```

Expected key results:

- `Mach-O 64-bit executable arm64`
- `mpv v0.41.0`
- code signing verification succeeds with the ad-hoc signature generated by the
  bundle step

Directly running `mpv.app/Contents/MacOS/mpv --version` from the terminal may
abort because the app binary initializes Cocoa application registration. Test
the app bundle through Finder or `open`.

## Package as mpv_r

The Mac packaging script can use a locally built `mpv.app` as its source app:

```sh
VERSION=v0.3-arm64-test \
MAC_SOURCE_APP=/Users/mba2026/Documents/codex_hisyo/VideoReviewPlayer/build-src/mpv/build/mpv-r-arm64-local/mpv.app \
packaging/scripts/build-mac.sh
```

This creates:

```sh
dist/mpv_r-mac-v0.3-arm64-test.zip
```

The script renames the bundle to `mpv_r.app`, injects the mpv_r icon and config,
sets the bundle name and bundle identifier, copies documents, and ad-hoc signs
the resulting app.
